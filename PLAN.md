# Aurora — Development Plan

**Last reviewed:** 2026-10-31
**Project type:** Static multi-page website (12 Polish-language pages for the fictional travel brand Aurora Travel, a KP_Code Digital Studio demonstration project) built with vanilla ES modules and modular CSS, with a Service Worker, a Node.js build and validation toolchain, a Vitest/jsdom regression suite and manual Netlify deployment of `dist/`
**Plan status:** Active
**Primary source:** `AUDIT.md` (final technical audit, 2026-10-31); every open finding was re-verified against the current sources
**Previous plan:** [`docs/archive/plans/PLAN-2026-09-28.md`](docs/archive/plans/PLAN-2026-09-28.md)

## Planning principles

- The plan reflects the verified repository state at review time. Main items are checked only when all required subtasks and their verification are complete.
- Changes target the canonical sources: the root HTML pages, `css/`, `js/`, `service-worker.js`, `assets/` and `scripts/`. `dist/` is generated by `npm run build` and is never edited.
- Any change to the CSS or JS bundle, `index.html`, `offline.html`, `site.webmanifest` or runtime-cached images and fonts completes the intentional cache-version update in `docs/pipeline-notes.md`: raise `VERSION`, run `npm run record:sw-bundles`, pass `npm run build`, and keep the record and the worker in the same change.
- Page edits leave the inline theme bootstrap unchanged unless its CSP hash in `_headers` is reviewed and updated.
- Completed significant changes are recorded in `docs/CHANGELOG.md` under its entry policy. Resolved audit findings are closed in `AUDIT.md` under the rules in `AGENTS.md`.
- Options recorded as considered but not selected in `docs/archive/improvements/` are not planned. These include CI or automated deployment, lint or format tooling, a Node.js version declaration, extending `check:sw-bundles` to precached pages and a single theme-bootstrap variant.
